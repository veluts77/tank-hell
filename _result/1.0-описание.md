# Tank Hell — описание проекта

## Назначение

**Tank Hell** — десктопная 2D-игра в жанре артиллерийского симулятора (аналог Scorched Earth / Worms-like механики разрушаемого ландшафта). Игрок кликом мыши запускает снаряд по баллистической траектории; при попадании в землю или танк возникает взрыв, разрушающий рельеф, после чего обломки осыпаются.

Стек: **Kotlin / JVM 8**, UI на **Swing**, сборка **Gradle** (мультимодульный проект). Запуск кроссплатформенный: macOS / Windows / Linux.

## Структура модулей

| Модуль | Роль | Зависимости |
|--------|------|-------------|
| `main` | Точка входа (`MainKt`), application + Shadow JAR | `ui` |
| `ui` | Swing-окно, игровой цикл, виджеты отрисовки | `core` |
| `core` | Доменная логика без UI-зависимостей | — |

Разделение слоёв: доменные сущности живут в `core`, виджеты в `ui` оборачивают их и отвечают за рендеринг.

## Запуск и сборка

```bash
./gradlew build      # сборка всех модулей
./gradlew run        # запуск приложения
./gradlew :main:build
```

- Kotlin `1.9.0`, JVM toolchain `8`
- Главный класс: `MainKt`
- Плагин Shadow для упаковки fat JAR

## Архитектура рантайма

```
Main.kt
  └─ Frame (JFrame + Runnable)
       └─ бесконечный цикл repaint()
            └─ GamePanel.paintComponent()
                 ├─ drawScene()      — отрисовка в BufferedImage
                 └─ processLogic()   — тик сущностей
```

**Игровой цикл** совмещён с отрисовкой: `Frame.run()` вызывает `repaint()`, а в `GamePanel.paintComponent()` выполняются и логика, и sleep (~25 мс → ~40 FPS). Используется двойная буферизация через `BufferedImage` 800×600.

Порядок отрисовки: рельеф → падающие блоки → танки → взрывы → снаряды.

## Доменная модель (`core`)

### `GameField`
Матрица `BooleanArray` размера width×height: `true` — земля, `false` — воздух. Координата `(0,0)` — левый верхний угол.

- Инициализация рельефа: синусоидальные холмы (`y > 200·sin(0.01·x) + 300`)
- `at(x, y)` — проверка ячейки
- `subMatrixFor(explosion)` — вырезка подматрицы под зону взрыва (с учётом «нависающей» земли сверху)
- `applySubMatrix(...)` — безопасная по границам запись подматрицы обратно в поле

### `Tank`
Прямоугольник 40×20. Под действием гравитации смещается вниз на 10 px за тик, пока не коснётся земли или дна поля.

### `Bullet`
Баллистика: `x = x0 + P·t·cos(α)`, `y = y0 − P·t·sin(α) + 0.1·t²`. Столкновение с землёй — по точке позиции; с танками — через `Area.intersects` (пока не реализован).

### `Explosion`
Расширяющийся круг: радиус растёт на `radius / speedFactor` за тик до целевого `radius`.

### `FallingDustBlock`
После взрыва из вырезанной земли формируется блок пыли: круглая область «вырезается», затем ячейки попиксельно падают вниз (до 11 проходов за тик). По завершении матрица применяется обратно к `GameField`.

### `Area`
AABB (`x, y, width, height`). Метод `intersects` — заглушка (`return false`).

## UI-слой (`ui`)

| Компонент | Назначение |
|-----------|------------|
| `Frame` | Окно, поток с бесконечным `repaint()` |
| `GamePanel` | Оркестрация тиков, ввод мыши, тайминги |
| `GameFieldWidget` | Рендер рельефа (заливка фона + вертикальные линии земли) |
| `TankWidget` | Цветной прямоугольник танка |
| `BulletWidget` | Красный овал снаряда, коллизии, создание взрыва |
| `ExplosionWidget` | Красный расширяющийся овал, создание FallingDustBlock |
| `FallingDustBlockWidget` | Попиксельная отрисовка падающей земли |

**Ввод:** клик мыши создаёт `BulletWidget` в точке клика (угол=1, мощность=10). Создание взрыва по клику закомментировано.

**Сценарий:** при старте спавнятся 3 танка (оранжевый, серый, пурпурный). Танки падают на рельеф. Снаряды при попадании в землю/танк порождают взрыв → падающую пыль → обновление рельефа. Уничтожение танков (`processTankWounds`) — TODO, всегда `false`.

## Текущее состояние геймплея

Реализовано:
- разрушаемый ландшафт и осыпание земли после взрыва;
- баллистика снаряда и столкновение с рельефом;
- гравитация танков относительно земли;
- визуальный цикл взрыва.

Не завершено / заглушки:
- `Area.intersects` → попадание в танк фактически не работает;
- `processTankWounds` → танки не получают урон;
- нет полноценного управления прицелом/мощностью, ходов, UI HUD;
- нет тестов.
