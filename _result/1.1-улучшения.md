# Tank Hell — возможные улучшения

Ограничение: стек остаётся **Java/Kotlin + JVM**, кроссплатформенный запуск (macOS / Windows / Linux). Ниже — приоритезированный список с учётом текущего прототипа.

## Критичные дефекты (блокируют геймплей)

1. **Реализовать `Area.intersects`**  
   Сейчас всегда `false`, поэтому `BulletWidget.collided(tankWidgets)` никогда не срабатывает — попадания по танкам невозможны.

2. **Реализовать `processTankWounds`**  
   Метод-заглушка; танк не уничтожается при попадании взрыва/снаряда. Нужна модель HP или мгновенное уничтожение при пересечении с зоной взрыва.

3. **Исправить позицию взрыва танка**  
   `TankWidget.explode()` использует стартовые `xPos/yPos`, а не текущие координаты из `Tank` — взрыв появляется не там, где танк упал.

4. **Вынести игровой цикл из `paintComponent`**  
   `Thread.sleep` и логика внутри отрисовки Swing — антипаттерн: блокирует EDT, ломает предсказуемость FPS и реагирует на системные repaint. Нужен отдельный игровой поток / `javax.swing.Timer` / фиксированный timestep с `invokeLater` только для отрисовки.

## Геймплей и UX

5. **Управление стрельбой**  
   Сейчас клик создаёт снаряд с фиксированными `angle=1`, `power=10`. Добавить прицел (угол), шкалу мощности, выбор активного танка, поочерёдные ходы.

6. **Полноценная коллизия снаряд ↔ танк**  
   После `intersects` — исключать «свой» танк из попадания, учитывать размер hitbox, опционально урон от радиуса взрыва, а не только от точки снаряда.

7. **Физика танков на склонах**  
   Сейчас опора проверяется одной точкой (середина низа). Имеет смысл проверять несколько точек / выравнивать танк по поверхности, чтобы не «зависал» и не проваливался в неровности.

8. **Очистка земли под падающим танком**  
   `processTankFalling` затирает подматрицу пустотой — сомнительная механика (танк «вырезает» ландшафт). Лучше не модифицировать рельеф при падении, а только читать коллизию.

9. **Минимальный HUD**  
   Индикатор хода, угол/мощность, HP танков; убрать или спрятать отладочные таймеры (`showTime` / `showInnerTime`).

10. **Победа / поражение и рестарт**  
    Условия конца раунда, кнопка новой игры без перезапуска JVM.

## Архитектура и качество кода

11. **Выделить `GameSession` / `GameEngine` в `core`**  
    Оркестрация тиков сейчас в `GamePanel` (UI). Перенос правил в core упростит тестирование и смену UI (Swing → Compose Desktop и т.п.) без смены домена.

12. **Инверсия зависимостей виджет ↔ домен**  
    Виджеты создают доменные объекты внутри; лучше инжектить/хранить ссылку на доменную сущность, а виджету оставить только `draw`.

13. **Исправить утечку доменных деталей в UI**  
    Например, `Bullet.withinField` назван наоборот относительно использования (`flownAwayFrom = withinField.not()`); угол в радианах передаётся как `Int` без конверсии — сделать явный API (градусы → радианы).

14. **Убрать обработку `ArrayIndexOutOfBoundsException` как контроль потока**  
    В `GameField` / `FallingDustBlock` границы лучше проверять явно (`withinField`), а не ловить исключения.

15. **Иммутабельность / value-объекты**  
    `Area` как `data class`; координаты танков/пуль — согласованный API (`position()`, без дублирования полей в виджете).

## Производительность

16. **Оптимизация рендера рельефа**  
    `GameFieldWidget` рисует по одной вертикальной линии на столбец — приемлемо для 800×600, но при росте разрешения лучше кэшировать `BufferedImage` рельефа и инвалидировать только dirty-регионы после взрывов.

17. **Оптимизация `FallingDustBlockWidget.draw`**  
    На каждую «грязную» точку вызываются `translate` туда-обратно — заменить на отрисовку в локальных координатах или пакетную заливку.

18. **Кэшировать `area()`**  
    В коде есть TODO «место для оптимизации»: `Tank.area()` / `Bullet.area()` создают новый объект каждый кадр — кэш или переиспользуемый буфер.

19. **Ускорить симуляцию осыпания**  
    `FallingDustBlock.fall` — O(width·height) × 11 за тик. Для больших кратеров рассмотреть column-based «песочные» столбцы или симуляцию только dirty-колонок.

## Инфраструктура и сопровождение

20. **Юнит-тесты на `core`**  
    Баллистика, `intersects`, вырезка/применение подматрицы, завершение взрыва и falling-блока. Сейчас тесты закомментированы в Gradle.

21. **Обновить toolchain**  
    Kotlin 1.9.0 и JVM 8 — рабочий минимум; целесообразно Kotlin 2.x и JVM 17/21 LTS при сохранении кроссплатформенности.

22. **Конфигурация через параметры**  
    Размер поля, FPS, гравитация, радиус взрыва — вынести из магических чисел в конфиг/constants.

23. **Упаковка дистрибутива**  
    Shadow JAR уже подключён; добавить jpackage / документацию «как запустить на трёх ОС» для пользователей без IDE.

24. **Логирование вместо `printStackTrace`**  
    В `GamePanel` при ошибке ставится `isHealthy = false` и печатается стек — для отладки ок, для продукта нужен понятный fallback UI.

## Возможные эволюции продукта (без смены стека)

25. **Compose for Desktop** как альтернативный UI-модуль при сохранении `core` — проверка чистоты доменного слоя.  
26. **Локальный hot-seat на двоих** (уже почти заложено несколькими танками).  
27. **Разные типы снарядов** (радиус, гравитация, «копатель»).  
28. **Процедурная генерация карт** вместо одной синусоиды.  
29. **Звук взрывов/выстрелов** через `javax.sound` / TinySound — без нативных зависимостей, ОС-независимо.

### Рекомендуемый порядок работ

1. Починить `intersects` + урон танков + позицию взрыва.  
2. Вынести игровой цикл с EDT.  
3. Добавить управление выстрелом и HUD.  
4. Покрыть `core` тестами и подчистить границы матриц.  
5. Оптимизировать рендер/осыпание по мере необходимости.
